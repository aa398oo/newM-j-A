# 用户体验优化清单（UX Backlog）

> 来源：真机试用与代码走查。每条都是「功能存在，但用起来别扭」的问题。
> 与 `BUILD-STATUS.md` 的区别：后者记「能不能跑」，这里记「好不好用」。
> 新发现的问题一律按 `UX-NN` 追加，不删旧条目——已修的把状态改成 ✅ 并注明版本。

## 严重度定义

| 级别 | 含义 |
|---|---|
| P0 | 用户会认为是 bug（数据错、操作无效、状态不同步） |
| P1 | 明显不顺手，但能用 |
| P2 | 锦上添花 |

## UX-01 模组装完不刷新已安装列表 ｜ ✅ 已修（v0.1.1-dev，待真机验证）

**位置**：`app/src/main/java/dev/mineport/launcher/ui/mods/ModsDialog.kt` 安装回调

**现象**：点「安装」成功后，顶部「已安装 N 个模组文件」仍是旧数字，要关掉对话框重开才更新。用户第一反应是「是不是没装上」。

**原因**：`ModInstaller.install(...).onSuccess { count -> message = ... }` 里没有调 `refreshInstalled()`。

**修法**：`onSuccess` 里补 `refreshInstalled()`。

**验收**：装一个模组后，不必关闭对话框，计数立刻 +1。

---

## UX-02 安装过程没有进度 ｜ ✅ 已修（v0.1.1-dev，待真机验证）

**位置**：同上，`ModInstaller.install` 已有 `onFile: (label, done, total) -> Unit` 回调，Dialog 没接。

**现象**：装带依赖的模组（如 Sodium → 自动补 Fabric API）时只看到一个转圈，不知道装到第几个、共几个、正在装谁。

**修法**：把 `onFile` 接到状态，显示「正在安装 2/4：fabric-api-0.92.2.jar」+ 线性进度条。

**验收**：装 4 个依赖的全过程中，进度文字从 1/4 走到 4/4。

## UX-03 已安装的模组仍显示「安装」按钮 ｜ ✅ 已修（v0.1.1-dev）

**现象**：搜索结果的模组如果已经装过，按钮还是「安装」，可以重复点，第二次会重新下载覆盖。

**修法**：按文件名（`<modid>-<version>.jar`）或命中 project 的已装文件名集合，命中时按钮显示「已安装」并禁用。

**注意**：Modrinth 搜索结果不含具体文件名，只能按 slug/标题前缀做启发式匹配；宁可漏判也不要误判成「已安装」。

**验收**：装完 Sodium 后，搜索结果里 Sodium 那一行的按钮变成「已安装」。

## UX-04 点「安装」前不知道会装几个 ｜ ✅ 已修（v0.1.1-dev）

**现象**：依赖是隐式补的。点「Sodium」实际装了 Sodium + Fabric API，用户毫无预告。

**修法**：安装前先 `resolveDependencies` 拿列表，弹确认框：「将安装 2 个文件：sodium.jar、fabric-api.jar」，确认后才下载。

**代价**：多一次网络往返（依赖解析已经要请求各 project 的版本列表，确认框只是把结果先展示）。

**验收**：点安装后先看到依赖清单，取消则不下载任何文件。

## UX-05 搜索结果没有图标 ｜ P1

**位置**：`ui/mods/ModsDialog.kt` 结果列表。

**现状**：只有标题 + 描述 + 下载量，纯文字。Modrinth API 返回里其实有 `icon_url`。

**修法**：
1. `ModrinthHit` 增加 `icon_url` 字段
2. 引入 Coil（`io.coil-kt:coil-compose`）加载网络图片
3. 列表项左侧 40dp 圆角图标，加载失败显示首字母占位

**代价**：APK 增加约 400 KB；需要 `INTERNET` 权限（已有）。

**验收**：搜索 "sodium" 后每行左侧出现模组图标。

## UX-06 没有更新检测 ｜ P2

**现象**：已装模组有新版本时零提示。

**修法**：以文件名反查 Modrinth（`/v2/version_file/<sha1>` 接口，下载时已经存了 sha1），比对最新版本号，在已安装列表标「可更新」。

**依赖 UX-01 先把已安装列表做准**。

## UX-07 没有「打开 mods 目录」入口 ｜ ✅ 已修（v0.1.1-dev，复制路径）

**现象**：想看装了哪些 jar、想手动放一个 jar，无处可去。

**修法**：对话框底部加「导出到下载目录」或直接用 `FileProvider` 分享目录 zip；更简单的是显示完整路径 + 复制按钮。

**验收**：能看到并可复制 `mods` 目录的绝对路径。

## UX-08 品牌图标只有占位 ｜ ✅ 已修（v0.1.1-dev）

**位置**：`app/src/main/res/drawable/ic_launcher_foreground.xml`、`mipmap-anydpi-v26/ic_launcher.xml`

**现象**：启动器只有一个纯色方块 + 字母 M，切换器里和别的 App 放一起完全认不出。没有多个密度，也没有圆角/椭圆变体。

**修法**：设计一版「像素方块 + 信号青」图标（与 DESIGN-STYLE 主色一致），导出 48/72/96/144/192dp 五档 + adaptive icon foreground/background 两层；同步 `ic_launcher_round`。

**验收**：桌面启动器、最近任务、应用详情三处显示同一套图标且清晰。

## UX-09 没有启动画面 ｜ ✅ 已修（v0.1.1-dev）

**现象**：冷启动从点击图标到首页出现有 1–2 秒白屏，观感廉价。

**修法**：用 `androidx.core:core-splashscreen`：背景 `#0E1116` + 居中品牌图标 + 首页就绪后 `setKeepOnScreenCondition { ready }` 淡出。

**验收**：冷启动过程中不再出现纯白屏。

## UX-10 空状态是纯文字 ｜ ✅ 已修（v0.1.1-dev，实例/下载两处）

**位置**：`InstancesScreen.kt`（暂无实例）、`DownloadsScreen.kt`（还没有下载）、`AccountCard.kt`（没有账号）

**现象**：只有一行灰字，没有下一步动作引导。

**验收**：三个空状态都能一键跳到对应操作。

## UX-11 等宽数字未落地 ｜ ✅ 已修（v0.1.1-dev）

**位置**：`ui/theme/Theme.kt`

**现象**：DESIGN-STYLE 要求帧率/内存/版本号/下载速度用等宽体，实际全用默认字体，数字跳动时宽度抖动。

**修法**：`Typography` 增加 `mono` 变体（`FontFamily.Monospace`），在内存、版本号、下载进度、CPU% 处使用。

**验收**：设置页诊断卡里的数字不会因位数变化而左右抖动。

## UX-12 游戏内 HUD 未按规范 ｜ 🟡 部分修（v0.1.1-dev：轮盘描边+选中外扩；摇杆/动作键待真机后重绘）

**位置**：`ui/input` 与 `GameActivity` 的 ComposeView 覆盖层

**现象**：规范写的是「摇杆半透明环 + 中心点」「动作键 1.5px 描边圆 + 极淡填充」，实际是简单圆形 + 文字，视觉噪点多。

**修法**：按规范重绘：摇杆 `alpha 0.25` 环 + 内圈渐变；动作键 48dp 描边圆、按下填充加深；轮盘中心显示当前动作图标、打开时背景压暗 40%。

**验收**：进游戏后 HUD 不遮挡视野，按键边界清晰。

## UX-13 DESIGN-STYLE.md 编码损坏 ｜ ✅ 误判（2026-11-26 核查）

**位置**：`android/docs/DESIGN-STYLE.md`

**原判断**：文件用 GBK 保存，GitHub 渲染成 `瑙嗚椋庢牸瑙勮寖` 乱码。

**核查结论（撤销本条）**：文件本身是 **UTF-8 无 BOM**（首字节 `23 20 E8`），用严格 UTF-8 解码器（`new UTF8Encoding($false, $true)`）验证全部 19 个 `.md` 文件均合法，GitHub 显示正常。

乱码的真正来源是**读取方式**：PowerShell 的 `Get-Content` 未指定编码时按系统 ANSI（本机 GBK）解码，把已是 UTF-8 的中文读成乱码。

**教训（已写入纪律）**：
- 读文档一律 `Get-Content -Encoding UTF8`；
- 判断编码用字节级严格解码，不看终端显示；
- 报「文件坏了」之前先确认不是工具解码错。

**验收**：`[System.IO.File]::ReadAllBytes` + 严格 UTF-8 解码不抛异常。

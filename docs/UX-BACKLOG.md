## UX-01 模组装完不刷新已安装列表 ｜ ✅ 已修（v0.1.1-dev，待真机验证）

**位置**：`app/src/main/java/dev/mineport/launcher/ui/mods/ModsDialog.kt` 安装回调

**现象**：点「安装」成功后，顶部「已安装 N 个模组文件」仍是旧数字，要关掉对话框重开才更新。用户第一反应是「是不是没装上」。

**原因**：`ModInstaller.install(...).onSuccess { count -> message = ... }` 里没有调 `refreshInstalled()`。

**修法**：`onSuccess` 里补 `refreshInstalled()`。

**验收**：装一个模组后，不必关闭对话框，计数立刻 +1。

## UX-02 安装过程没有进度 ｜ ✅ 已修（v0.1.1-dev，待真机验证）

**位置**：同上，`ModInstaller.install` 已有 `onFile: (label, done, total) -> Unit` 回调，Dialog 没接。

**现象**：装带依赖的模组（如 Sodium → 自动补 Fabric API）时只看到一个转圈，不知道装到第几个、共几个、正在装谁。

**修法**：把 `onFile` 接到状态，显示「正在安装 2/4：fabric-api-0.92.2.jar」+ 线性进度条。

**验收**：装 4 个依赖的全过程中，进度文字从 1/4 走到 4/4。

## UX-03 已安装的模组仍显示「安装」按钮 ｜ ✅ 已修（v0.1.1-dev）

**现象**：搜索结果的模组如果已经装过，按钮还是「安装」，可以重复点，第二次会重新下载覆盖。

**修法**：按文件名（`<modid>-<version>.jar`）或命中 project 的已装文件名集合，命中时按钮显示「已安装」并禁用。

**注意**：Modrinth 搜索结果不含具体文件名，只能按 slug/标题前缀做启发式匹配；宁可漏判也不要误判成「已安装」。

**验收**：装完 Sodium 后，搜索结果里 Sodium 那一行的按钮变成「已安装」。

## UX-04 点「安装」前不知道会装几个 ｜ ✅ 已修（v0.1.1-dev）

**现象**：依赖是隐式补的。点「Sodium」实际装了 Sodium + Fabric API，用户毫无预告。

**修法**：安装前先 `resolveDependencies` 拿列表，弹确认框：「将安装 2 个文件：sodium.jar、fabric-api.jar」，确认后才下载。

**代价**：多一次网络往返（依赖解析已经要请求各 project 的版本列表，确认框只是把结果先展示）。

**验收**：点安装后先看到依赖清单，取消则不下载任何文件。

## UX-05 搜索结果没有图标 ｜ P1

**位置**：`ui/mods/ModsDialog.kt` 结果列表。

**现状**：只有标题 + 描述 + 下载量，纯文字。Modrinth API 返回里其实有 `icon_url`。

**修法**：
1. `ModrinthHit` 增加 `icon_url` 字段
2. 引入 Coil（`io.coil-kt:coil-compose`）加载网络图片
3. 列表项左侧 40dp 圆角图标，加载失败显示首字母占位

**代价**：APK 增加约 400 KB；需要 `INTERNET` 权限（已有）。

**验收**：搜索 "sodium" 后每行左侧出现模组图标。

## UX-11 等宽数字未落地 ｜ ✅ 已修（v0.1.1-dev）

**位置**：`ui/theme/Theme.kt`

**现象**：DESIGN-STYLE 要求帧率/内存/版本号/下载速度用等宽体，实际全用默认字体，数字跳动时宽度抖动。

**修法**：`Typography` 增加 `mono` 变体（`FontFamily.Monospace`），在内存、版本号、下载进度、CPU% 处使用。

**验收**：设置页诊断卡里的数字不会因位数变化而左右抖动。

## UX-13 DESIGN-STYLE.md 编码损坏 ｜ ✅ 误判（2026-11-26 核查）

**位置**：`android/docs/DESIGN-STYLE.md`

**原判断**：文件用 GBK 保存，GitHub 渲染成 `瑙嗚椋庢牸瑙勮寖` 乱码。

**核查结论（撤销本条）**：文件本身是 **UTF-8 无 BOM**（首字节 `23 20 E8`），用严格 UTF-8 解码器（`new UTF8Encoding($false, $true)`）验证全部 19 个 `.md` 文件均合法，GitHub 显示正常。

乱码的真正来源是**读取方式**：PowerShell 的 `Get-Content` 未指定编码时按系统 ANSI（本机 GBK）解码，把已是 UTF-8 的中文读成乱码。

**教训（已写入纪律）**：
- 读文档一律 `Get-Content -Encoding UTF8`；
- 判断编码用字节级严格解码，不看终端显示；
- 报「文件坏了」之前先确认不是工具解码错。

**验收**：`[System.IO.File]::ReadAllBytes` + 严格 UTF-8 解码不抛异常。

# 界面重构 v2（2026-11-28 讨论定案）

> 本节记录与用户逐条讨论确定的方向。**尚未动手实现**，实现前以本节为准。
> 核心变化：竖屏 → **全站横屏**；底部导航 → **左侧 NavigationRail**；配色 深色 → **蓝白浅色为主**；术语「实例」→「**版本**」。

## UX-14 全站横屏 + 左侧导航 rail（P0）

- **放弃竖屏**，只做横屏一套布局：`android:screenOrientation="sensorLandscape"`（允许左右翻转，不锁死方向）。
- 导航从底部改到**屏幕左侧** `NavigationRail`，宽 **80dp**，图标在上、文字在下。
- 五项：**启动 / 下载 / 设置 / 个性化 / 更多**（「个性化」为新增，见 UX-18）。
- 选中态：**左侧贴边 3dp 主蓝色条 + 主蓝文字**，不用 Material 默认胶囊背景（深色/浅色切换时更稳，也不和内容区按钮抢视觉）。
- rail 底部放版本号 `v0.1.0-alpha`，不占内容区。
- 理由：横屏时高度只有约 400dp，顶部 tab 浪费最宝贵的高度；rail 是 Material 3 宽屏标准做法。
- **技术要点**：`MainActivity` 加 `android:configChanges="orientation|screenSize|smallestScreenSize|keyboardHidden"`；**`GameActivity` 不能加**（GL 上下文绑 Surface，旋转必须重建 Surface，加了会黑屏）。

## UX-15 蓝白配色（P0）

| 用途 | 色值 |
|---|---|
| 品牌主蓝 | `#1E5EFF` |
| 背景渐变 | `#F4F8FF` → `#E8F0FF` |
| 卡片 / 输入框 | `#FFFFFF` + 1dp `#E3EAF5` 边框 |
| 可启动状态强调 | `#22D3A6`（保留绿，和蓝形成对比） |
| 危险 / 删除 | `#EF4444` |
| 深色模式背景 | `#0E1116`（保留现有深色） |
| **游戏内 HUD** | **必须保持深色**（`#0E1116` 半透明）——游戏画面背景不可控，浅色 HUD 会看不见 |

- 默认为**浅色**，深色作为选项。
- 纯白 `#FFFFFF` 铺底刺眼（夜间、横屏大面积），用浅蓝灰 `#F4F8FF` 起点。

## UX-16 首页启动台（P0）

布局（横屏，rail 右侧）：

```
┌─────────┬──────────────────────┬─────────────────────────┐
│  ▣ 启动  │  [封面图 16:9]        │   版本画廊（网格）        │
│  ↓ 下载  │  新的版本             │  ┌────┐ ┌────┐ ┌────┐   │
│  ⚙ 设置  │  1.20.1 · Fabric      │  │1.21│ │FAB │ │ +  │   │
│ 🎨个性化 │  ▶ 启动游戏（大按钮）  │  └────┘ └────┘ └────┘   │
│  ⋯ 更多  │  [12模组][光影✓][轮盘✓]│                         │
└─────────┴──────────────────────┴─────────────────────────┘
```

- **术语统一**：用户可见文案一律用「版本」替代「实例」（`管理版本` / `最近游玩` / `新建版本` / `版本设置` / `删除版本` / `版本卡片`）。内部类名、变量名保持 `Instance*` 不变（只改文案）。
- **亮点一：主角是版本封面，不是头像**——封面图 + 版本号 + 加载器色块（Fabric 米黄 / Forge 橙 / Quilt 紫 / Vanilla 灰）+ 模组数与光影状态。
- **亮点二：「准备度」三连 chip**——`12 模组` / `光影 ✓` / `轮盘 ✓`，每枚可直接点进对应管理页；未就绪时变行动号召（`+ 装 Fabric` / `+ 加光影`），把三层菜单压成一行。
- **亮点三（备选）：短码分享**——`ShortCode.kt` 已有能力，首页右下角露出「分享版本」按钮。

│  ▣ 启动  │  ▸ 推荐      │  搜版本号 [1.20.1            🔍]  │

│         │              │  └────────────────────────────┘  │

- **三栏分工**：rail（我在哪）→ 分类 180dp（下载页内部选什么）→ 内容（具体哪个版本）。
- 分类四项：**推荐 / 正式版 / 快照 / 全部**，默认落「推荐」。
- 推荐页：最新正式版大卡片 + 4 个常用版本 + 全部正式版折叠（默认 10 个，可展开）。
- 搜索框固定在内容区顶部；横屏键盘约吃掉 40–50% 高度，可接受（`adjustResize` 默认行为）。
- **装完交互**：弹「版本已就绪」→「去启动」跳首页启动台并选中新版本。
- **待定**：常用版本选 `1.20.1 / 1.20.4 / 1.19.2 / 1.18.2`（模组生态友好），待用户确认。
- 快照默认藏起来，避免小白误装（快照经常崩）。

## UX-18 个性化页（P1，新增第 4 项导航）

四组内容，右侧内容区放**实时预览卡**（改色/改主题立即看到效果）：

1. **主题**：浅色 / 深色 / 跟随系统
2. **主色调**：蓝 / 绿 / 紫 / 橙 / 粉（只换强调色，背景与卡片保持中性）
3. **动效**：界面动画开关（关闭=瞬间切换，省电）、减少动画（无障碍，尊重系统设置）
4. **游戏内 HUD**：轮盘大小（200/220/260dp）、透明度（40%–100%）、位置（左下/右下）

存储用 `Prefs.kt`（`SharedPreferences`，十几个键，不用 DataStore）：
`theme / accent / animations / wheelSize / wheelAlpha / wheelCorner`。

`Theme.kt` 参数化：`MineportTheme(pack: ThemePack? = null, accent: Color = BrandBlue, dark: Boolean = false, content)`；色板引用换成语义名（`brandPrimary` / `brandSoft` / `brandBorder`）。

## UX-19 主题包系统（P2，创作者生态）

**三层结构**：内置预设（普通用户）→ 本地主题包（创作者）→ 在线主题市场（未来）。

**`.mptheme` = zip**，内部：

```
my-theme/
├── theme.json      必需
├── background.png  可选，首页背景图（≤2MB）
└── icon.png        可选，缩略图（≤256KB）
```

**`theme.json`**：

```json
{
  "name": "深海", "author": "玩家A", "version": "1.0", "base": "dark",
  "colors": {
    "primary": "#4DD0E1", "onPrimary": "#00363A",
    "background": "#0B1620", "surface": "#132530",
    "onSurface": "#E6F4F7", "outline": "#2A4550",
    "success": "#4ADE80", "danger": "#F87171"
  },
  "shape": { "cornerRadius": 16 },
  "density": "compact",
  "background": "background.png"
}
```

**开放边界（只开放数据，不开放代码）**：

| 可以 | 不可以 |
|---|---|
| 8 个语义颜色 | 执行代码 |
| 背景图（PNG/JPG） | 自定义字体（版权风险） |
| 圆角半径（0–28dp） | 任意布局脚本 |
| 密度（compact/normal/comfortable） | 外部链接 |
| 深/浅色基底 | 读取设备信息 |

**校验清单**：`name` 非空 ≤40 字；颜色必须合法 `#RRGGBB`；`cornerRadius` 0–28；背景图 ≤2MB 且 PNG/JPG；解压用白名单文件名防路径穿越（`../../`）。

**流程**：个性化页「导入主题包」→ 文件选择器 → 解析校验 → 预览 → 应用（写入 `filesDir/themes/<id>/`）。

**实现顺序建议**：UX-14/15/16/17 先做（全站骨架 + 首页 + 下载），UX-18 次之，UX-19 最后（依赖前三者稳定）。

## UX-20 动画风格：灵动 + 平滑（P0）

**总原则**：短时长、先快后慢、轻微弹性、错峰入场。**灵动靠 spring，平滑靠 ease-out**，不要夸张弹跳、不要旋转翻转、不要长位移。

### 时长表

| 档 | 时长 | 用途 |
|---|---|---|
| micro | 120ms | 按压反馈、图标切换 |
| small | 180ms | 单项内容变化、勾选、chip 切换 |
| medium | 260ms | 页面切换、卡片展开、弹层 |
| large | 340ms | 主题切换、全屏转场 |

### 曲线

- **默认**：`CubicBezierEasing(0.2f, 0f, 0f, 1f)`（快进慢出，即现 `Motion.Ease`）
- **按压**：`Spring(dampingRatio = 0.8f, stiffness = StiffnessMedium)`——轻微回弹，不晃
- **强调**：`EaseOutCubic` 用于数值滚动
- **禁止**：线性、幅度 > 1.1 的过冲

### 场景规范

| 场景 | 做法 |
|---|---|
| 页面切换（rail 五个 tab） | 淡入 + 上下 8dp 位移，260ms，方向随 tab 顺序（向左/向右滑） |
| 列表入场 | 每项 30ms 错峰，最多 8 项，之后整体一起出现 |
| 卡片按压 | 0.96 缩放 + spring 回弹，释放 180ms 复原 |
| Tab/rail 选中 | 图标 1.0 → 1.1 → 1.0，180ms；左侧 3dp 蓝条高度动画 220ms |
| 三连 chip | 状态变化时背景色 crossfade 180ms + 文字 1px 位移 |
| 下载进度 | 进度条平滑增长（animateFloatAsState，无跳变）；不用转圈，用 `PixelDotsLoading` |
| 骨架屏 | 灰色块 + 1.4s 呼吸（alpha 0.4 ↔ 0.8），不用 CircularProgressIndicator |
| 主题切换 | 全局颜色 crossfade 300ms（`animateColorAsState` 包一层） |
| 数字统计 | 从 0 滚到目标值，600ms ease-out（`Animatable`） |
| 空状态 | 图标 24dp → 64dp 弹性入场 + 文案淡入 |

### 禁止清单

- ❌ 大面积位移（> 24dp）
- ❌ 旋转/翻转转场（`Rotate` 页面切换）
- ❌ 超过 400ms 的动画
- ❌ 无限循环动画（除 loading）
- ❌ 动画期间阻塞输入
- ❌ 游戏内（GLSurfaceView 上）叠加任何动画——游戏画面必须零干扰

### 性能约束

- 动画只影响 Compose 层，游戏在独立 `:game` 进程，**互不影响**
- 低端机可关（UX-18 的「界面动画」开关），关闭后所有 `animate*AsState` 直接取终值
- 用 `graphicsLayer` 做变换，避免 `Modifier.offset` 触发重排

### 现有基础

`android\app\src\main\java\dev\mineport\launcher\ui\motion\Motion.kt` 已有：
`ScreenMs = 220`、`Ease = CubicBezierEasing(0.2f, 0f, 0f, 1f)`、`PressSpring`、`Modifier.pressScale(source)`、`EnterFromBottom(index)`、`PixelDotsLoading`。

## UX-21 局内按键：移动摇杆 + 动作轮盘（P0，当前优先级最高）

> 背景：竞品 Starling 有四种可编辑触控方案（摇杆/D-pad/点击/准星）。我们的轮盘有设计感，但布局写死、不能收起、挡视野。本节定案：**移动用浮动摇杆、动作用轮盘**，各司其职。

### 21.1 总体形态

```
┌───────────────────────────────────────────────────┐
│                                                   │
│      ╭─────╮                         ╭──╮        │
│      │  ○  │ ← 摇杆头                │⚔ │        │
│      │ 基座 │                        ╰──╯        │
│      ╰─────╯                        收起态小球    │
│   移动摇杆（常驻，按下才出现）                       │
└───────────────────────────────────────────────────┘
```

- **移动摇杆**：常驻左侧，只负责移动，浮动摇杆（按下出现、拖动控向、松手消失）。
- **动作轮盘**：默认右下，负责跳跃/攻击/使用/潜行等，**可收起成小球**（用户明确要求：常驻会挡视野）。
- 两个轮盘各用一根手指，互不干扰（多指按 pointerId 分流，见 UX-23）。

### 21.2 移动摇杆（常驻）〔2026-11-28 修订：轮盘改为摇杆〕

**为什么改**：轮盘是固定 8 方向的「离散」输入，摇杆是「连续」输入且手指可以任意位置按下——手游上摇杆更顺手，也和 Starling 的默认方案一致。

**形态**：**浮动摇杆**。

```
       按下前                     按下并拖动后
   （看不见，只占位置）        ┌──────────────┐
                               │      ○ 头     │
                               │   ╲   │       │
                               │    基座       │
                               └──────────────┘
```

- 手指在**左半屏**任意位置按下 → 以按下点为圆心出现基座
- 拖动 → 摇杆头跟随（最大偏移 = 基座半径）
- 松手 → 摇杆消失、所有方向键松开
- 默认不透明度 70%，可调 20%–100%
- 基座大小可调（140/180/220dp），摇杆头约基座 40%

**方向换算**——仍是 8 方向，避免 MC 斜向速度不一致：

| 角度（相对正上） | 键 |
|---|---|
| ±22.5° | W |
| 22.5°–67.5° 右 | W + D |
| ±22.5° 右 | D |
| 67.5°–112.5° 下 | S + D / S / S + A |
| ±22.5° 左 | A |
| 67.5°–112.5° 上左 | W + A |

**规则**：
- 死区：偏移 < 基座半径的 **15%** → 松开所有方向键（停下）
- 方向切换**先松开旧键、再按新键**（避免 W 与 S 同时按住打架）
- 指头抬出屏幕或接收到 CANCEL → 立即全松
- **不触发视角**：摇杆的 pointer 只归移动
- **冲刺（双击 W）暂不支持**——摇杆做不到双击；后续可加「推到底保持 0.4 秒自动冲刺」

**实现**：`MovePad.kt` 改为浮动摇杆模型——`onDown(x,y)` 记录锚点，`onMove(x,y)` 算偏移向量 → 角度 → 方向键集合，`onUp()` 全松。

### 21.3 动作轮盘（可收起）

**展开态**：8 个扇区，每个可绑定一个键。默认绑定：

| 扇区 | 键 | 说明 |
|---|---|---|
| 上 | Space | 跳跃 |
| 右上 | E | 打开物品栏 |
| 右 | 鼠标左键 | 攻击 / 挖掘 |
| 右下 | Q | 丢弃物品 |
| 下 | Shift | 潜行 |
| 左下 | 鼠标右键 | 使用 / 放置 |
| 左 | F5 | 切换视角 |
| 左上 | ESC | 菜单 |

- 空位可清空（显示为暗色空洞，减少误触）
- 按住持续（攻击/使用/移动都支持长按）
- 中心显示「−」收起按钮

**收起态**：48dp 半透明小球（30%–50%，可调）
- 点小球 → 展开
- 点轮盘中心「−」→ 收起
- 长按小球 1.5 秒 → 进入编辑模式
- 拖动小球 → 移动位置（吸附屏幕边缘）
- 展开后 **4 秒无操作自动收起**（可在设置关闭）
- 球上固定显示「⚔」图标（不显示动态信息，保持安静）

### 21.4 编辑模式

**进入**：长按轮盘中心/小球 1.5–3 秒。

**可调整**：
- 拖动：改位置（吸附 8dp 网格）
- 双指缩放：改大小（0.6×–1.8×）
- 点击空位：弹出键位选择器（W/A/S/D/Space/Shift/Ctrl/E/Q/1–9/F1–F12/ESC/TAB/鼠标左右键）
- 长按空位：清空绑定
- 底部「完成」退出

### 21.5 存储

`Prefs.kt`（SharedPreferences）：
`movePadAlpha / movePadSize / actionPadExpanded / actionPadAlpha / actionPadBallX / actionPadBallY / actionPadAutoCollapse`

按键绑定表存 JSON：`filesDir/action-pad.json`（8 个槽位 → 键码）。

### 21.6 与 GameHostLayout 的接线

新增两个 owner：

```kotlin
const val OWNER_MOVE_PAD = 2   // 移动摇杆（已有 OWNER_GAME = 0, OWNER_WHEEL = 1）
const val OWNER_ACTION_PAD = 3 // 动作轮盘
```

`dispatchTouchEvent` 按 pointerId 记账：落在移动摇杆圆内 → `OWNER_MOVE_PAD`；落在动作轮盘（或小球）内 → `OWNER_ACTION_PAD`；其余 → `OWNER_GAME`（视角）。

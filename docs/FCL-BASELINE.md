# 与 FCL 对齐基线（对标矩阵 + 测量协议）

> 原则：**FCL 是参照系，不是天花板。** 功能不阉割，性能不低于，体验三处超越。
> 建立时间：2026-11-19。基准设备：红米 K70 至尊版（天玑 9300+ / Immortalis-G720 MC12 / 16GB / Android 16）。

## 一、三条对齐线

1. **功能对齐**：FCL 有的核心能力，P1–P2 必须全有，不做「我们的阉割版」。
2. **性能对齐**：同设备、同版本、同分辨率、同后端，帧数 ≥ FCL 的 100%，启动耗时 ≤ FCL 的 100%。
3. **体验超越**：三处不追对齐而要超越——交互、下载、模组管理（详见第四节）。

## 三、性能基准测量协议

在基准设备上用 FCL 跑以下 5 组，每组记录 5 项。**这是所有性能验收的唯一依据**，不测就没有目标。

| 组 | 配置 | 目的 |
| --- | --- | --- |
| A | 1.20.1 原版，无 mod，720p，GL4ES | 基础帧率基线 |
| B | 1.20.1 + Sodium/Lithium 优化包，720p | 优化上限 |
| C | 1.12.2 原版，720p | 旧版本对照 |
| D | 1.20.1 + 最轻光影（如 MakeUp Ultra Fast），720p | 光影可行性与帧数 |
| E | 1.20.1 + 30 mod 整合包 | 启动耗时与内存 |

每组记录：
1. 平均帧率（进入世界后静止 60 秒采样）
2. 1% low 帧率（卡顿严重程度）
3. 启动耗时（点启动到主菜单/进入世界）
4. 内存峰值（dumpsys meminfo 或 FCL 内显示）
5. 是否可用（崩溃/黑屏/画面错误）

> 待补：FCL 在 A 组的具体帧数（用户已报「100 帧以上」，需补版本、分辨率、后端、是否装优化 mod）。

## 四、三处超越点（不对齐，而是做得更好）

1. **交互**：满屏按键 → 意图/Action 系统 + 动作轮盘。模组从 10 个到 100 个，主屏按键数量不变。
2. **下载**：多步手动 → 三次点击进游戏；多源自动切换 + 断点续传 + 人话进度。
3. **模组**：手动对版本 → 依赖递归补齐、重复拦截、崩溃归因到具体 mod、一键回滚。
4. **分享**：无 → 6 位短码分享整机配置（唯一传播钩子）。

## 五、使用方式

- 每周对照一次矩阵：缺项即进 backlog，不靠记忆。
- 每次性能改动后跑一遍协议（至少 A 组）：低于基线即视为回归。
- 光影相关结论只能来自 D 组实测，不接受推测。

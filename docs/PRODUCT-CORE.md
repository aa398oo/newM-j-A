# 项目核心策略（立项版）

> 状态：已定稿，作为后续所有开发决策的判据。2026-11-19 定，2026-11-20（周五）开工。
> 任何新功能进入开发前，先对照本文第二节与第四节。

## 一、产品定位

**硬核 Minecraft Java 版玩家的移动化工具。**

- 名称：**newM-j-A** 是工程代号（开发期显示名），正式品牌名待定，见 BRAND.md；包名 dev.mineport.launcher 保持不变。
- 不承诺「手机玩 MC 很流畅」，承诺「配好就能跑，跑不动会自动降档而不是崩溃」。
- 目标平台：骁龙（Adreno）+ 天玑（Mali/Immortalis）。
- 目标市场：小众但有强需求的细分市场，判断标准看留存，不看装机量。

## 一.5 产品独立性（与 FCL 的关系）

我们是**独立产品**，不是 FCL 的移动版、分支或续作。

1. **叙事**：对外不称「FCL 手机版」「FCL 续作」；表述为「为手机重新设计的 Java 版启动器」。
2. **品牌**：不复用其名称、图标、配色、文案语气；产品名不得含 FCL / PCL 字样。
3. **技术血缘必须披露**：复用 FCLCore（GPL-3.0）。分发 APK 即构成衍生作品，**整个应用须以 GPL-3.0 开源并保留版权声明**。这条与「闭源商业化」互斥，需接受。
4. **致谢页**必须列出上游：FoldCraftLauncher、Amethyst-Android、PojavLauncher、GL4ES、LWJGL、OpenJDK。
5. **兼容不承诺**：不宣称兼容 FCL 的实例目录、配置文件或房间码。

## 二、八条核心策略

| # | 策略 | 一句话定义 |
| --- | --- | --- |
| 1 | 正版优先登录 | 微软设备码登录为主流程；离线登录需点击切换并明示代价 |
| 2 | 三次点击进游戏 | 打开 → 一键开玩 → 自动装好并启动；复杂选项全部折叠 |
| 3 | 模组全自动 | 递归装前置、拦截重复、崩溃归因到具体 mod、可一键回滚 |
| 4 | 交互重构 | 意图/Action 系统 + 动作轮盘，拒绝满屏按键映射；模组从 10 到 100 个主屏不变 |
| 5 | 光影尽力而为 | 探测 → 试跑 → 自动回退；骁龙走 Turnip，天玑走系统 Vulkan；承诺「能开」不承诺「流畅」 |
| 6 | 配置即内容 | 6 位短码分享整机配置（只存引用清单，不含游戏本体与 mod 文件） |
| 7 | 联机不自建 | 保留多人游戏入口 + LAN 发现 + 服务器状态探测 + 穿透教程；中继只留接口不实现 |
| 8 | 启动性能工程 | AppCDS 归档、-Xverify:none、Metaspace 扩容、Mixin 冲突检测、崩溃急救 |

## 三、优先级（P1 之外的都不开发）

- **P1 能进游戏** —— 唯一生死线。壳 + JRE + LWJGL + GL4ES + FCLCore 出画面。
- **P1.5 短码分享** —— 唯一传播钩子，含 10–20 套官方种子配置。
- **P2 模组生态 + 动作轮盘** —— 差异化主体。
- **P3 光影 + 启动优化** —— 加分项。
- **P4 崩溃归因、设备体检、正版细节打磨**。

## 四、明确不做

1. 自建中继、P2P 打洞（合规与运维成本；保留 `MultiplayerProvider` 接口，将来条件成熟再实现）
2. 售卖游戏内容或游戏内功能（触碰 EULA）
3. 广告墙、阻挡核心体验的付费墙
4. 内置热门服推荐、服务器列表爬虫
5. CurseForge 集成（需 API key 且条款受限；先做粘贴 CF 链接导入兜底）
6. 承诺任何光影包的固定帧数

## 五、可验收指标

- 30 个 mod 的实例：首次启动 ≤ 60s，二次启动 ≤ 35s
- 200 个 mod 的整合包：不 OOM，首次启动 ≤ 180s，内存峰值 ≤ 设备 RAM 的 45%
- 从打开应用到进入游戏：≤ 3 次点击
- 短码导入到进入游戏：≤ 3 分钟（含下载，家宽）
- 光影：骁龙 8 系 720p + 最轻光影 ≥ 25fps；天玑 9300 ≥ 20fps，不达标自动无光影 45fps+

## 六、商业模式（最小闭环）

- 只做「赞助 + 中继额度成本转嫁」；不做内购抽成、不做广告。
- 先覆盖服务器成本（短码服务 + 可选中继），不以盈利为目标。
- 若将来做中继，前置条件：月活过万、有主体、有备案、只放行 25565、限速限人数。

## 七、周五（2026-11-20）开工第一批任务

1. **二进制接入**：从 Amethyst-Android apk 提取 `libjvm/libjava/liblwjgl/libgl4es/libopenal` 与 natives，落到 `app/src/main/jniLibs/arm64-v8a/` 与 assets，验证 `llvm-readelf` 架构正确、能 dlopen。
2. **打通 JNI → JVM**：让 `JvmLauncher.start()` 真正创建 JavaVM，读 `java.version`，把 JRE 版本显示在游戏画面上即算通过。
3. **GL4ES 出画面**：`eglSwapBuffers` 链路接上，全屏清屏为纯色即算通过（替代当前测试三角形）。
4. **接入 FCLCore.jar**：构建出可在 Android 运行的 jar，跑通版本清单拉取（Mojang piston-meta → 界面列表）。
5. **构建可安装 APK**：本机无 Android SDK，走 GitHub Actions 云构建产出 arm64 APK。
6. **真机首测**：目标「点一下能进到游戏主菜单」，记录启动耗时与首个报错原文。

> 顺序不可调换：1 和 2 不通，后面全部无意义。
>
> 实现说明（2026-11-21）：JVM 创建后运行的是 HotSpot，它的类加载器只读 classpath 上的 jar，读不到 APK 里的 dex。
> 因此第 2 步不在 JVM 内回调 Kotlin 类，而是由 JNI 直接读 `java.version` 回传壳层；
> FCLCore.jar 从第 4 步起作为 classpath 上的 jar 在 JVM 内运行，Kotlin 壳只负责界面与文件落位。

## 八、开工前需要准备

1. 基准测试设备已确认：红米 K70 至尊版（天玑 9300+ / Immortalis-G720 MC12 / **16GB RAM** / Android 16 / 512GB 存储 / 无 root）。默认堆 2048MB，上限 3072MB。
2. Amethyst-Android 的 apk（用于提取预编译二进制）或已解包好的 `jniLibs` 目录。
3. 一个 GitHub 账号与仓库（云构建与分发都需要；本机无 git/gh）。

## 九、已知风险（不回避）

- 手机跑 Java 版本质是错配，中低端机体验有限，市场上限不高。
- 首次启动无法显著加速（Mixin 转换与类加载是必要开销），只能优化首次耗时与二次提速。
- 光影兼容性依赖「机型 × 光影包」实测积累，不是写完代码就可用。
- 联机体验完全交给用户自己的穿透工具，我们只降低「填地址」的门槛。

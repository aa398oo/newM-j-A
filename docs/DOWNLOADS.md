# 下载子系统设计（newM-j-A）

> 定位：下载不是"功能"，是 P1 的**硬前提**——装不上就等于进不去。
> 用户原话（2026-11-19）："下载连接也很重要，我使用 PCL 时总是失败。"
> 本文是工程施工规格，不是营销描述。状态：设计定稿，待开工实现。

## 一、为什么别的启动器"总是失败"

失败几乎从不是"网速慢"，而是下面四类结构性问题：

1. **源单点**：启动器只认一个下载源（官方或某个镜像）。该源对某个文件 404 / 限速 / 掉线，任务直接失败，重试仍走同一个源。
2. **无文件级状态**：整包当作一个任务。第 486 个文件失败，前面 485 个的进度无法复用，用户看到的是"下载失败"而不是"哪个文件、为什么"。
3. **无断点续传**：移动网络切换、锁屏、后台被杀，几百 MB 客户端要从 0 重来。
4. **安装器联网**：Forge/NeoForge 的 installer.jar 运行时自己再联网抓 libraries，这一步最脆——用户在电脑上都常失败，手机上失败率更高。

PCL 类启动器的典型失败点集中在：**Forge/NeoForge 安装器阶段**、**CurseForge 整合包**（需 API key 且部分作者禁止第三方分发）、**镜像缺文件**（镜像是异步同步的，新版本发布后一段时间内 objects 可能缺失）。

## 二、目标与验收

- 首次一键开玩成功率达到 **99%**（1.20.1 + Fabric + 优化包）。
- 任意单文件失败可**独立重试 / 换源 / 跳过**，不影响已完成的部分。
- 4G 下下载途中切 WiFi、锁屏 5 分钟、杀进程重进，都能**继续**而不是重来。
- 失败提示必须包含：文件、源、HTTP 状态或异常、以及**下一步可点的动作**。

## 三、源策略：三级降级

每个文件按顺序尝试，前一级失败才降级，最多三跳：

1. **主源**：启动时对候选源做并行探测（取三个小文件，测 TTFB 与成功率），选最优者为主源。候选：国内镜像（BMCLAPI 类）、官方源、用户自填镜像。
2. **备份源**：主源返回 404 / 403 / 429 / 超时，立即换下一个，不重试同一个源。
3. **官方源兜底**：镜像缺 objects 时回落 Mojang 官方域名（慢但完整）。

规则：**镜像优先、官方兜底、永不因单源失败而整体失败**。源列表可配置，不放死在代码里。

## 四、文件级任务模型

下载的最小单元是**一个文件**，每条记录至少包含：

- 逻辑路径（相对 .minecraft 的路径）
- URL 列表（按优先级）
- 期望大小 + sha1（Mojang 元数据里就有）
- 状态：pending / downloading / verifying / done / failed
- 已下载字节数（断点用）

落盘为一个本地任务库，App 重启后按状态续跑。**"已存在且 sha1 匹配"的文件秒级跳过**——这同时解决了重复安装与换源后的复用问题。

## 五、断点续传与并发

- 用 HTTP Range 请求 + '.part' 临时文件；完成后校验 sha1 再改名。
- 并发自适应：初始 8 路，遇 429/403 降到 4，再降到 2；连续成功 20 个文件后缓慢回升——目标是"不被 CDN 当爬虫"，而不是最大吞吐。
- 后台继续：用 Android 的 WorkManager 承载长任务，配合前台通知（"已下载 231/486 · 12.4 MB/s"），锁屏不断。
- 退避：单文件重试 3 次，指数退避 1s / 4s / 12s，之后换源。

## 六、安装器离线化（关键差异点）

Forge/NeoForge 的 installer 是"下载器 + 补丁器"二合一。常规做法是下载 installer 再运行它，让它在手机上联网抓两百个 libraries——这是失败率最高的一段。

做法：解析 installer 的 install_profile.json（1.13+）或 version.json（旧版），**预先把它需要的 libraries 全部下好**放进共享库目录，再运行 installer。这样 installer 阶段几乎不发网络请求，只做本地 patches 与解压。

顺带解决：Java 版本与安装器匹配检查（1.17+ 需 17，1.20.5+ 需 21），版本不对直接拦下来给明确提示，而不是让安装器跑到一半崩。

## 七、Modrinth 与整合包

- 模组/光影/资源包/整合包统一走 Modrinth API v2（免 key），按选定 MC 版本 + 加载器过滤，安装前解 depends 递归拉前置。
- .mrpack 整合包：读 manifest 里的 files 列表逐条下载，校验 hashes，按 overrides 覆盖配置。
- CurseForge：**不做 API 集成**（需 key 且有条款限制）。只保留"粘贴 CF 链接 / 拖入本地 zip"的导入兜底，并在界面明说原因。

## 八、错误分类与用户动作

不输出"下载失败"四个字，按类给结论：

| 类别 | 判定 | 界面给的结论 | 可点动作 |
| --- | --- | --- | --- |
| 网络不通 | DNS 失败 / 连接超时 | 连不上服务器 | 换源 / 检查网络 / 设代理 |
| 源缺文件 | 404 / 403 | 这个源缺此文件 | 自动换源（已自动）/ 改官方源 |
| 被限流 | 429 | 服务器限速 | 自动降并发重试 |
| 校验失败 | sha1 不匹配 | 文件损坏 | 重新下载该文件 |
| 磁盘满 | ENOSPC | 空间不足（还需 X MB） | 清理空间 |
| 权限 | EACCES | 无法写入目录 | 换存储位置 |

## 九、代理与自定义源

设置页提供：HTTP/SOCKS5 代理、自定义镜像前缀（替换官方域名）、"官方源优先"开关。这三项直接解决"我的网络环境就是不行"这一类无解问题——比任何重试逻辑都有效。

## 十、本地导入兜底

兜底路径必须存在：从本地 zip / '.minecraft' 目录 / 他人分享的整合包导入，全程不联网。当所有源都不可用时，应用仍可用——这是"下载做得再好也会有人网络不行"的现实妥协。

## 十一、实现依赖

- 网络：**当前用标准库 `HttpURLConnection`**（已经是「不自己写 socket」；Range、超时、重定向都够用，零新增依赖）。
  需要连接池、代理、HTTP/2 时再换 OkHttp——替换点只在 `FileDownloader.downloadOne` 与 `VersionManifestClient.httpGet` 两个函数里。
- 并发：Kotlin 协程 + 受限并发调度（Semaphore），不用裸线程池。
- 后台：WorkManager（长任务 + 前台通知）——待接。
- 任务库：Room 或轻量 SQLite 表，避免 JSON 全量重写（486 条状态频繁写盘会抖）——待接。
- 哈希：MessageDigest SHA-1，边下边算，避免二次读盘——当前在下载完成后整文件校验（1.20.1 的 client.jar 量级可接受），边下边算放到队列阶段。

## 十二、开工顺序（对齐 P1）

1. 任务库 + 单文件下载器（含 Range、sha1、重试、换源）——**先跑通，再做界面**。
2. 版本 JSON 解析 + libraries/assets 全量下载（1.20.1 原版）。
3. 安装器离线化（Fabric 简单，先做；Forge/NeoForge 后做）。
4. Modrinth 搜索与整合包导入。
5. 界面：一键开玩 + 手动五分栏 + 人话进度。

验收方式：用一台手机 + 一次真实的"从零装 1.20.1 Fabric"跑通，中间故意断网两次、切一次 WiFi，看能否续上。

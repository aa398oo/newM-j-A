# 多 AI 协作约定（AI-COLLAB）

本项目的疑难问题采用「双 AI 会诊」模式：本执行体负责动手实现与验证，参考文献（外部技术评审）负责源码级复核与方案建议。

## 1. 协作分工

| 角色 | 职责 | 不做什么 |
| --- | --- | --- |
| 本执行体（DSH 内的编码代理） | 读代码、改代码、编译、真机验证、写文档、维护台账 | 不对无法验证的结论下判决 |
| 参考文献（外部评审） | 依 FCL 源码逐行复核、给出实现要点、指出遗漏的初始化契约 | 不能访问本机设备与构建环境 |

## 2. 交接方式（重要）

**问题必须落成文件，答复也必须落成文件**，不靠截图滚动读取：

1. 需要请教时，把问题整理成一段可直接粘贴的文本（含背景、已确认事实、具体疑问、期望产出）。
2. 由用户在参考文献侧提问，并让参考文献**把答复写成文件**放到工作区，例如：
   - `X:\android\docs\REVIEW-<主题>.md`（答复）
   - `X:\项目文件体检-2026-11-23.md`（体检报告类）
3. 本执行体直接 `read` 文件，摘出可执行项，逐条落地到代码与台账。

## 3. 提问模板

```
背景：<项目 + 当前链路 + 平台/SoC>
已确认事实：<日志/反汇编/源码位置等硬证据>
具体疑问：
1) ...
2) ...
期望产出：<代码 / 时序 / 检查清单 / 结论>
```

## 5. 纪律

- 参考文献给的结论必须落到可验证的动作上（编译通过、日志出现某关键字、文件出现某字段），否则视为待验证假设。
- 与本执行体实测冲突时，以实测为准，并回问参考文献「为何与实测不符」。
- 每次协作结束后，把结论补进 `handoff\决策台账-2026-11-21.md`（D 编号）与本文案例库。
